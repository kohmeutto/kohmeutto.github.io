격자 적응

40. 격자 적응

격자를 처음에 얼마나 촘촘히 잡아야 할지는 풀어 보기 전에는 모릅니다. 해가 급하게 변하는 자리가 어디인지 미리 알 수 없기 때문입니다.

그래서 두 가지를 씁니다.

방법 무엇을 하나 노드 수
r-적응 있는 노드를 필요한 자리로 옮긴다 그대로
h-정제 노드를 더 만든다 늘어난다
$$\text{둘은 서로 다른 일을 합니다. 대신 쓰는 관계가 아닙니다}$$

노드를 옮기는 것만으로 안 되는 때가 있습니다. 아무리 잘 옮겨도 노드가 모자라면 해를 못 담습니다. 그때 h-정제가 나섭니다.

이 문서가 다루는 파일

파일 하는 일
relaxMesh.m 노드를 옮긴다
AdjointTensionRelaxer2D.m 언제까지 옮길지 정한다
meshSufficiency.m 격자가 충분한지 보고, 모자라면 얼마나 늘릴지 낸다
@ResidueSolverNR2D/solveSteady.m 부족하면 늘려서 다시 푼다. 솔버의 메서드다
interpToMesh.m 격자가 바뀔 때 해를 옮겨 담는다

1. 노드를 옮긴다 — r-적응

1.1 어디로 옮기는가

해가 급하게 변하는 자리로 모읍니다. 그 판단 기준으로 두 길이를 견줍니다.

$$\ell_{\text D} = \sqrt{\frac{p}{\lvert\partial q/\partial u\rvert}}$$

이 길이는 「확산이 소스의 변화를 얼마 만에 따라잡는가」를 뜻합니다.

어느 쪽이 큰가 뜻
$\ell_{\text D}$ 가 간선보다 훨씬 크다 이 자리는 완만하다. 노드가 남아돈다
$\ell_{\text D}$ 가 간선보다 작다 이 자리는 급하다. 노드가 모자란다

이 비를 제곱해 간선마다 「당기는 힘」을 줍니다. 급한 자리의 간선이 세게 당기므로 노드가 그쪽으로 모입니다.

$$\omega_i = \left(\frac{\ell_{\text D}}{\ell_{\text{node}}}\right)^2$$

1.2 어떻게 푸는가

노드 위치를 미지수로 두고 라플라스 방정식을 풉니다.

$$\mathcal L\,X_{\text{new}} = \mathbf b_X$$

$\mathcal L$ 는 위에서 정한 힘을 가중치로 삼은 라플라스 연산자입니다. 그래프 위에서 「이웃과 균형을 이루는 자리」를 찾는 것입니다.

1.3 안 옮기는 노드

세 가지는 못박습니다.

못박는 것 왜
계면 위의 노드 옮기면 물질 경계가 흐트러진다
바깥 경계 위의 노드 옮기면 영역 모양이 달라진다
점이나 선으로 등록한 영역의 노드 그 자리를 지정한 뜻이 사라진다

못박은 노드가 하나도 없는 덩어리가 생기면 $\mathcal L$ 를 못 풉니다. 그런 경우 좌표에 무한대나 NaN 이 들어가므로, 코드가 그것을 잡아내고 그 회차의 옮기기를 건너뜁니다.

1.4 옮긴 뒤에 할 일

meshM.convertToTriangles();      % 삼각형을 다시 잇는다
meshM.updateMetrics(physM);      % 계량을 다시 잰다

노드가 움직이면 삼각형이 겹치거나 뒤집힐 수 있습니다.

1.5 왜 함수인가

relaxMesh 는 기억해 둘 것이 없습니다. 격자를 받아 노드를 옮기고 끝냅니다. 언제까지 옮길지를 정하는 일은 따로 떼어 AdjointTensionRelaxer2D 가 맡습니다. 그쪽은 회차마다 값을 기억해야 하므로 클래스입니다.

2. 언제까지 옮기는가 — AdjointTensionRelaxer2D

2.1 기억하는 것

이름 무엇
PrevRho 직전 바퀴의 $\rho_{\mathrm{int}}$
RhoTolNow 이번에 쓸 허용오차. 솔버가 넣어 준다
IsMeshFrozen 이미 멈췄는지
ChangeRatio 이번에 노드가 얼마나 움직였는지
MeshFreezeRatio $\rho$ 를 안 잴 때 쓰는 기준. 사용자가 정하는 값이다

2.2 멈추는 조건 — $\rho$ 가 더 안 바뀌면 멈춘다

$$\bigl\lvert \rho^{(k)} - \rho^{(k-1)}\bigr\rvert < \text{RhoTol} \quad\Longrightarrow\quad \text{멈춘다}$$

RhoTol 은 **「$\rho$ 를 이보다 정확히 알 필요가 없다」**는 값입니다. adaptiveTolerances 가 냅니다.

$$\text{RhoTol} = \frac{1+\rho^2}{\rho}\,\ln\frac{1}{\varsigma_{\min}} \sqrt{\frac{2}{\ln(1/\text{ResTol})}}$$

격자를 옮겨도 $\rho$ 가 그 안에서만 움직이면 더 옮길 이유가 없습니다. $\rho$ 를 정확히 재도 그 차이를 알 수 없기 때문입니다.

$$\text{\textbf{손으로 고른 수가 없습니다}}$$

2.3 $\rho$ 를 안 재는 경우

NewtonStepControl 이 'Adaptive' 가 아니면 $\rho$ 를 안 잽니다. 그때는 노드가 얼마나 움직였는지로 봅니다.

$$\frac{\max\lVert \mathbf x^{\text{new}} - \mathbf x^{\text{old}}\rVert}{\bar h} < \texttt{MeshFreezeRatio}$$

이쪽은 손으로 고른 수입니다. 비교 대상으로만 쓰는 길이라 남겨 두었습니다.

옛 판에는 조건이 하나 더 있었습니다. 「간선 길이 비의 변화가 1 미만」이라는 것인데, 1 의 근거가 없었습니다. 노드가 안 움직이면 간선 비도 안 바뀌므로 첫 조건과 겹칩니다. 뺐습니다.

2.4 한 번 멈추면 다시 안 옮긴다

$$\texttt{IsMeshFrozen = true} \text{ 가 되면 그 뒤로는 그냥 돌아옵니다}$$

격자가 계속 흔들리면 잔차를 비교할 기준이 없어집니다. 자리를 잡은 뒤에는 격자를 고정하고 해에만 집중하는 편이 낫습니다.

처음부터 안 옮기려면 sv.UseRAdapt = false 로 두면 됩니다. 그러면 sv.RAdaptOpt 도 없어집니다.

이 객체가 곧 sv.RAdaptOpt 입니다. 사용자가 MeshFreezeRatio 를 고치는 자리입니다.

sv.UseRAdapt = true;
sv.RAdaptOpt.MeshFreezeRatio = 1e-4;

sv.UseRAdapt = true 를 넣는 그 순간에 만들어집니다. solve 를 기다리지 않습니다. 그리고 solve 를 부를 때마다 새로 만들지 않고 이번 풀이의 기록만 비웁니다. 그래야 넣어 둔 값이 안 지워집니다.

3. 격자가 충분한지 본다 — meshSufficiency

3.1 무엇으로 판단하나

$$\nu_{\max} = \max_{\text{간선}} \lvert \nu \rvert, \qquad \nu = \left.\frac{\partial\ln p}{\partial u}\right\rvert \delta u$$

이 값은 「한 간선을 건너는 동안 $p$ 가 얼마나 변하는가」입니다.

$\nu_{\max}$ 뜻
$\le 1$ 충분하다. 한 간선에서 $p$ 가 두 배 넘게 안 변한다
$> 1$ 모자란다. 간선이 물성 변화를 못 따라간다

이 값은 trustRegionStep 이 이미 재고 있습니다. 걸음을 정할 때 쓰는 것과 같은 값입니다. 따로 계산하지 않습니다.

3.2 얼마나 늘려야 하는가

$$N_x^{\text{new}} = \bigl\lceil 1 + (N_x - 1)\,\nu_{\max} \bigr\rceil$$

이 식이 어디서 나오는지 보겠습니다.

간선 하나의 길이는 $N_x - 1$ 에 반비례합니다.

$$h \propto \frac{1}{N_x - 1}$$

$\nu$ 는 간선 길이에 비례하므로, 노드를 $\gamma_h$ 배로 늘리면 $\nu$ 도 $1/\gamma_h$ 배가 됩니다. $\nu_{\max}$ 를 1 로 만들려면 딱 $\nu_{\max}$ 배만큼 늘리면 됩니다.

$$\nu_{\max} \times \frac{N_x - 1}{N_x^{\text{new}} - 1} = 1$$

여기서 $N_x^{\text{new}}$ 를 풀면 위 식이 나옵니다. 여유를 위해 곱하는 상수가 없습니다. 필요한 만큼만 늘립니다.

3.3 나오는 것

info = meshSufficiency(dg, Nx_now, 'Nodes', mm.Nodes, 'DomainLx', Lx);
이름 무엇
info.nu_max 지금 값
info.sufficient $\nu_{\max} \le 1$ 인가
info.Nx_suggest 늘려야 할 $N_x$. 충분하면 그대로
info.edge_argmax 가장 큰 값을 낸 간선
info.h_argmax 그 간선의 실제 길이
info.h_ratio 그 길이가 공칭 $\ell_x/(N_x-1)$ 의 몇 배인지
info.vp_max 물성 변화의 세기

h_ratio 가 알려 주는 것이 있습니다.

h_ratio 뜻
1 근처 보통 간선이다. 격자 전체가 모자란다
1 보다 훨씬 크다 유난히 긴 간선 하나다. 그 자리만 문제다

4. 격자를 늘려 다시 푼다 — solveSteady

4.1 부르는 법

아무것도 안 정해도 됩니다. 기본이 켬입니다.

[U, r_norm, steady_info] = sv.solveSteady();

값을 고치려면 켠 것의 객체에 넣습니다.

sv.UseHAdapt = true;
sv.HAdaptOpt.MaxHRefine = 3;
이름 어디에 있나 뜻 기본
UseHAdapt 솔버의 속성 노드를 늘릴지 true
MaxHRefine sv.HAdaptOpt 몇 번까지 늘릴지 3
U_init 부를 때 주는 값 시작할 해 0

sv.UseHAdapt = false 이면 한 번만 풀고 끝납니다. r-적응만 도는 셈입니다. 그리고 sv.HAdaptOpt 가 없어집니다. 치면 그 자리에서 멈춥니다.

격자를 늘린 뒤 해를 어떻게 할지는 고를 값이 아닙니다. 0 에서 다시 시작합니다. 까닭은 4.4 절에 적었습니다.

4.2 도는 순서

푼다  →  nu_max 를 잰다  →  충분하면 끝
                        └  모자라면 Nx 를 늘려 격자를 다시 만들고 처음으로

4.3 멈추는 이유는 둘뿐

이유 언제
"충분" $\nu_{\max} \le 1$ 이 됐다
"MaxHRefine 도달" 정한 횟수를 다 썼다

이 둘 말고는 없습니다. 잔차가 크다고 해서 멈추지 않습니다.

그 까닭을 짚어 두겠습니다. 격자가 모자라서 안 풀리는 것인데, 안 풀린다고 격자를 안 늘리면 영원히 못 풉니다. 앞뒤가 뒤바뀐 판단입니다.

$\nu_{\max}$ 가 직전보다 안 줄었다고 멈추지도 않습니다. $\nu$ 는 간선 길이와 해의 변화를 함께 담은 값이라, 노드를 늘리면 분모가 커지지만 해도 달라져 분자가 바뀝니다. 오르내리는 것이 정상입니다.

4.4 해를 어떻게 넘기는가 — 고를 값이 아니다

격자를 새로 만들면 노드가 달라집니다. 전에 푼 해를 어떻게 할지가 문제인데, 고를 값이 아니라 문제의 성격이 정하는 값입니다.

어디 무엇을 하나
solveSteady 버리고 0 에서 다시 시작한다
solveTransient 옛 격자의 해를 새 격자로 옮겨 담는다

정상 문제는 0 에서 다시 시작합니다. 해가 하나뿐이라 버려도 같은 자리로 갑니다. 그리고 실측으로 옮겨 담는 쪽이 느리고 잔차도 나빴습니다. 격자가 같은 유일한 비교인 $f=10$ 에서 이랬습니다.

시간 잔차
옮겨 담기 13.35 s $4.80\times10^{-10}$
0 에서 다시 8.24 s $\mathbf{7.14\times10^{-11}}$

느린 까닭이 있습니다. 조 격자의 해가 틀렸으므로 옮기면 틀린 곳에서 시작합니다. 그러면 뉴턴이 다른 구역으로 끌려갑니다. 0 에서 시작하면 신뢰영역이 통제하는 경로를 그대로 탑니다.

$f=20$ 에서는 옮겨 담은 쪽이 정제를 한 번 덜 했는데도 2.7 배 느렸습니다. r-적응에서 세 방식을 견준 기록도 같은 결론이었습니다.

시간을 전진시킬 때는 다릅니다. 거기서 $u^n$ 은 물리적인 상태입니다. 버리면 다른 문제를 푸는 것이 됩니다. 50_시간전진.md 참조.

옛 판에는 UTransfer 라는 옵션이 있었습니다. 둘 중 하나를 고를 수 있었는데, 정상에서 옮겨 담는 쪽을 고를 이유가 없고 과도에서 버리는 쪽을 고르면 다른 문제를 푸는 것이라 없앴습니다.

4.5 나오는 것

이름 무엇
steady_info.reason 멈춘 이유
steady_info.sufficient 충분해져서 멈췄는가
steady_info.n_refined 몇 번 늘렸는가
steady_info.Nx_history 회차마다의 $N_x$
steady_info.nu_after_history 그 회차를 푼 뒤에 잰 $\nu_{\max}$
steady_info.res_history 회차마다의 잔차

5. 해를 옮겨 담는다 — interpToMesh

U_new = interpToMesh(Nodes_old, Elems_old, U_old, Nodes_new);

옛 격자의 삼각형 안에서 값을 선형으로 이어 새 노드 자리의 값을 냅니다. 새 노드가 옛 격자 밖에 있으면 가장 가까운 값을 씁니다.

격자를 늘릴 때와 시간을 전진시킬 때 둘 다 이 함수를 씁니다.

6. h-정제가 실제로 무엇을 해 주는가

정확도를 더해 주지는 않습니다.

노드 수를 똑같이 맞춰 놓고 견주어 보면 알 수 있습니다.

어떻게 오차
$N_x{=}64$ 에서 시작해 정제로 78 까지 늘림 거의 같음
처음부터 $N_x{=}78$ 로 품 거의 같음
$$\text{그러니 h-정제가 해 주는 일은 이것입니다}$$

알맞은 $N_x$ 를 사람이 안 정해도 됩니다.

문제마다 필요한 격자가 다른데, 그것을 미리 알 방법이 없습니다. 너무 작게 잡으면 안 풀리고, 너무 크게 잡으면 느립니다. h-정제는 풀어 보고 모자라면 딱 필요한 만큼 늘립니다.

그 대가로 시간이 몇 배 듭니다. 같은 문제를 여러 번 풀기 때문입니다. 한 번만 풀 것이면 알맞은 $N_x$ 를 아는 편이 빠릅니다. $N_x$ 를 모르는 채 여러 조건을 훑을 때 값어치가 있습니다.

7. 두 방법을 함께 쓰면

두 값이 나란합니다. 참이 켜는 것입니다.

sv.UseRAdapt = true;      % 노드를 옮길지
sv.UseHAdapt = true;      % 노드를 늘릴지

둘 다 솔버의 속성이고 기본이 켬입니다. 켜면 그 값을 담는 객체가 생깁니다.

켜기 생기는 것 그 안의 값
sv.UseRAdapt sv.RAdaptOpt MeshFreezeRatio
sv.UseHAdapt sv.HAdaptOpt MaxHRefine
UseRAdapt UseHAdapt 무엇이 도나
true true 옮기고 늘린다. 기본
false true 늘리기만
true false 옮기기만
false false 둘 다 안 함. 한 번만 푼다

둘은 서로 독립입니다. 옮기는 것은 노드 수를 안 바꾸고, 늘리는 것은 위치를 안 바꿉니다. 그래서 켜고 끄는 이름도 따로 두었습니다.

8. 주의할 것

격자를 바꾸면 캐시를 비워야 합니다. mm.Nodes 에 새 값을 넣으면 계량은 저절로 비워지지만, 물성 쪽은 따로 비워야 합니다.

physM.EvalCache = {};

solveSteady 이 끝날 때 이것을 합니다.

옮기기와 늘리기는 각자 다른 것을 봅니다. 옮기기는 디바이 길이를 보고, 늘리기는 $\nu_{\max}$ 를 봅니다. 하나가 잘 돈다고 다른 하나가 필요 없어지지 않습니다.

노드를 옮기면 $\nu_{\max}$ 가 오히려 커질 수 있습니다. 급한 자리로 노드를 모으면 그 자리의 해상도는 좋아지지만, 노드를 내준 자리의 간선이 길어집니다. 그러면 그쪽에서 $\lvert \nu\rvert$ 가 커집니다. 이상한 일이 아닙니다.
